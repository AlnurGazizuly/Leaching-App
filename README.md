## Overview

Lithium-ion battery recycling via hydrometallurgical leaching involves a large experimental search space defined by leaching agent, reducing agent, acid concentration, reductant concentration, temperature, and reaction time. Acquiring sufficient experimental data to cover this space is costly and time-consuming.

This work addresses two challenges: (1) limited labeled experimental data, and (2) the need for a practical tool to predict and optimize leaching recovery without additional experiments. Four Gradient Boosting Regressors (GBR) are trained, one per target metal (Li, Co, Mn, Ni), to predict recovery (%) from process conditions and feed composition. A separate GBM-driven data augmentation pipeline synthesizes physically constrained training samples, and a Flask web application exposes the trained model through an interactive interface that supports single-point prediction and parametric sweeps.

## Datasets

All datasets are located in the `Datasets used in the paper/` folder.

| File | Description | Rows |
|---|---|---|
| `original.xlsx` | Raw experimental leaching data compiled from the literature | ~250 |
| `final_synthesized_.xlsx` | Synthetic-only dataset generated by `Data_Augmentation.py` | ~5,000 |
| `Final_combined.xlsx` | Concatenation of original and augmented data used for model training | ~6,500 |

**Column schema** (shared across all three files):

| Column | Type | Description |
|---|---|---|
| `Li in feed %` | Numeric | Lithium content in black mass feed (wt%) |
| `Co in feed %` | Numeric | Cobalt content in black mass feed (wt%) |
| `Mn in feed %` | Numeric | Manganese content in black mass feed (wt%) |
| `Ni in feed %` | Numeric | Nickel content in black mass feed (wt%) |
| `Leaching agent` | Categorical | Acid used (e.g., H2SO4, HCl, citric acid) |
| `Type of reducing agent` | Categorical | Reductant used (e.g., H2O2, glucose) or "Unknown" if none |
| `Concentration, M` | Numeric | Leaching agent molarity (M) |
| `Concentration %` | Numeric | Reducing agent concentration (wt%) |
| `Time, min` | Numeric | Leaching duration (minutes) |
| `Temperature, C` | Numeric | Leaching temperature (°C) |
| `Li`, `Co`, `Mn`, `Ni` | Numeric (target) | Metal recovery (%), clamped to [0, 100] |

## Methodology

### Data Augmentation

`Data_Augmentation.py` generates synthetic leaching data to mitigate the limited experimental sample size. The pipeline runs as follows:

1. **Load and clean** the original dataset. Target values outside [0, 100] are removed and categorical strings are normalized to title case, with missing/null reducing agents mapped to "Unknown".

2. **Train GBMs** on the original data. One `GradientBoostingRegressor` is fitted per target metal (`Li`, `Co`, `Mn`, `Ni`) using 200 estimators, learning rate 0.05, and max depth 4. Metals with fewer than 5 valid observations are skipped.

3. **Estimate per-group noise** by computing within-condition residuals for each `(leaching agent, reducing agent)` group. The noise floor is set to 0.5 percentage points, and groups with fewer than 3 observations receive a default noise of 2.0 percentage points.

4. **Perturb process conditions** by resampling rows from each group and adding Gaussian noise scaled to 5% of each feature's observed range. Time and temperature are rounded to integers; rows without a reducing agent retain a concentration of 0.

5. **Predict and add noise**. The fitted GBMs predict recovery for each perturbed condition set, then calibrated Gaussian noise is added and predictions are clipped to [0, 100] and to the interval [group minimum - 5, group maximum + 5].

6. **Validate** the synthetic distribution against the original using mean, standard deviation, interquartile range, out-of-bounds rate, and per-group mean drift.

7. **Save** two output files: a synthetic-only dataset (~5,000 rows) and a combined dataset (original + 5x augmented per group).

Key parameters in `Data_Augmentation.py`:

```python
TARGET_TOTAL_ROWS  = 5000   # approximate row count for the synthetic file
AUGMENT_MULTIPLIER = 5      # augmentation factor per group for the combined file
NOISE_SCALE        = 0.04   # fallback noise as a fraction of within-group std
RANDOM_SEED        = 42
```

> The scripts were developed and tested in Google Colab. The `drive.mount` calls at the top of `Data_Augmentation.py` and `Model.py` are required for Colab execution. Update `INPUT_FILE`, `OUTPUT_FILE`, and `COMBINED_OUTPUT` paths to match your Drive layout before running.

### Model Training and Evaluation

`Model.py` trains and evaluates GBR models across four experiment configurations:

| # | Dataset | Categorical features |
|---|---|---|
| 1 | Original | Included |
| 2 | Original | Excluded (numeric only) |
| 3 | Combined | Included |
| 4 | Combined | Excluded (numeric only) |

For each configuration the script reports:

- **Table 2** — 80/20 train-test split metrics (R², RMSE, MAE, and delta columns comparing train vs test).
- **Table A** — 5-fold cross-validation training fold summary (mean ± std).
- **Table B** — 5-fold cross-validation validation fold summary (mean ± std).

And optionally saves three figures per experiment:

- **Parity plot** — predicted vs actual recovery for each metal.
- **Partial dependence plots (PDP)** — marginal effect of temperature, time, leaching concentration, and reducing agent concentration.
- **SHAP feature importance** — mean absolute SHAP value per original feature, plus a global average panel across all four metals.

GBR hyperparameters used during training:

```python
n_estimators    = 300
max_depth       = 4
learning_rate   = 0.05
subsample       = 0.8
min_samples_leaf = 5
random_state    = 42
```

The preprocessor applies median imputation to numeric features and one-hot encoding (ignoring unknown categories) to categorical features, wrapped in a `ColumnTransformer`.

## Web Application

`app.py` is a Flask application that serves the trained model (`finaltrial.pkl`) through a browser interface (`templates/index.html`). The interface is named **LeachLab** and provides:

- **Single-point prediction** — input feed composition and process conditions, receive predicted recovery (%) for Li, Co, Mn, and Ni.
- **Radar chart** — visual comparison of predicted recoveries across all four metals.
- **Parametric sweep** — four line charts showing predicted recovery vs temperature, leaching concentration, reaction time, and reducing agent concentration, with all other variables held constant at the entered values.
- **Optimization verdict** — automated interpretation of sweep results identifying which parameters are far from their single-variable optimum and estimating the potential gain in average recovery (percentage points).

Three REST endpoints are exposed:

| Endpoint | Method | Description |
|---|---|---|
| `/` | GET | Serves the LeachLab HTML interface |
| `/predict` | POST | Returns single-point recovery predictions as JSON |
| `/sweep` | POST | Returns parametric sweep data for all four variables |
| `/health` | GET | Returns model load status |

**Request schema for `/predict` and `/sweep`:**

```json
{
  "li_feed":        5.0,
  "co_feed":        20.0,
  "mn_feed":        10.0,
  "ni_feed":        10.0,
  "leaching_agent": "H2SO4",
  "leach_conc":     2.0,
  "reducing_agent": "H2O2",
  "reduce_conc":    5.0,
  "temp":           80,
  "time_min":       60
}
```

**Response schema for `/predict`:**

```json
{
  "status": "ok",
  "predictions": {
    "Li": 92.4,
    "Co": 88.1,
    "Mn": 75.3,
    "Ni": 83.7
  }
}
```

All prediction values are clamped to [0, 100] before being returned.

## Installation and Usage

### Running the Model Scripts

The training and augmentation scripts are designed for Google Colab. To run them:

1. Upload the repository to Google Drive.
2. Open `Data_Augmentation.py` or `Model.py` in Colab.
3. Update the file path variables at the top of each script to point to your Drive locations:

```python
# Data_Augmentation.py
INPUT_FILE      = '/content/drive/MyDrive/your_folder/original.xlsx'
OUTPUT_FILE     = '/content/drive/MyDrive/your_folder/final_synthesized.xlsx'
COMBINED_OUTPUT = '/content/drive/MyDrive/your_folder/Final_combined.xlsx'

# Model.py
FILE_PATH_ORIGINAL = '/content/drive/MyDrive/your_folder/original.xlsx'
FILE_PATH_COMBINED = '/content/drive/MyDrive/your_folder/Final_combined.xlsx'
```

4. Run all cells. The `drive.mount` call at the top of each script handles authentication.

To run locally (without Colab), remove or comment out the `drive.mount` lines and update paths to local file paths.

---

### Running the Web Application Locally

**Requirements:** Python 3.9 or later.

1. Clone the repository and navigate to the project root.

2. Install dependencies:

```bash
pip install -r requirements.txt
```

3. Ensure `finaltrial.pkl` is present in the same directory as `app.py`.

4. Start the Flask development server:

```bash
python app.py
```

5. Open `http://127.0.0.1:5000` in a browser.

For production deployment, use gunicorn:

```bash
gunicorn -w 2 -b 0.0.0.0:8000 app:app
```

> If `finaltrial.pkl` is not found, the server starts in degraded mode and all `/predict` and `/sweep` calls return a 503 error. Re-generate the artifact by running `Model.py` and serializing the returned model and preprocessor with `joblib.dump`.

## Feature Engineering

Five interaction and polynomial features are appended to the base numeric features before training. These are included in model training but excluded from SHAP and PDP displays to keep interpretations grounded in experimental variables.

| Feature | Formula | Physical interpretation |
|---|---|---|
| `Time_x_Temp` | Time × Temperature | Synergistic leaching effect |
| `Leach_Conc_x_Time` | Leaching conc. × Time | Acid consumption over time |
| `Temp_Squared` | Temperature² | Quadratic temperature curvature |
| `Time_Squared` | Time² | Diminishing returns at long leaching durations |
| `Acid_to_Reducer` | Leaching conc. / (Reducing conc. + 1e-6) | Stoichiometric acid-to-reductant ratio |

These features are added consistently in `Data_Augmentation.py`, `Model.py`, and `app.py` via the same `add_engineered_features` function to prevent train-serve skew.
